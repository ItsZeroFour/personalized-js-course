# Два указателя

## Идея

Два индекса движутся по массиву (или по двум массивам) по правилу, и каждый шаг
**отбрасывает** часть вариантов. Вместо перебора пар O(n²) — один проход O(n), часто
с O(1) дополнительной памяти.

## Встречные указатели в отсортированном массиве

Классика — пара с заданной суммой в **отсортированном** массиве:

```js
function pairWithSum(sorted, target) {
  let left = 0;
  let right = sorted.length - 1;
  while (left < right) {
    const sum = sorted[left] + sorted[right];
    if (sum === target) return [left, right];
    if (sum < target) left++;   // сумму можно увеличить только сдвигом левого
    else right--;               // уменьшить — только сдвигом правого
  }
  return null;
}
```

Почему корректно: если `sorted[left] + sorted[right] < target`, то `sorted[left]` не
даст нужную сумму ни с одним элементом (правее `right` мы уже всё отбросили, а левее —
элементы меньше). Значит, `left` можно отбросить.

Сигнал для паттерна: **отсортированный вход** или возможность отсортировать. Вариации:
3Sum (фиксируем один элемент, для остальных — два указателя, O(n²)), контейнер с
наибольшим объёмом воды, квадраты отсортированного массива.

## Быстрый и медленный указатель

Оба идут в одну сторону с разной скоростью:

```js
// удалить дубли из отсортированного массива на месте, вернуть новую длину
function removeDuplicates(nums) {
  if (nums.length === 0) return 0;
  let write = 1;                          // медленный: куда писать
  for (let read = 1; read < nums.length; read++) {   // быстрый: что читаем
    if (nums[read] !== nums[write - 1]) {
      nums[write] = nums[read];
      write++;
    }
  }
  return write;
}
```

Черепаха и заяц (Флойд) для связного списка: медленный делает шаг на 1, быстрый — на 2.
Встретились — есть цикл; быстрый дошёл до `null` — цикла нет. Когда быстрый дойдёт до
конца, медленный будет в **середине** списка.

## Перемещение элементов на месте

«Переместите все нули в конец, сохранив порядок остальных» — тот же шаблон read/write:

```js
function moveZeroes(nums) {
  let write = 0;
  for (let read = 0; read < nums.length; read++) {
    if (nums[read] !== 0) {
      [nums[write], nums[read]] = [nums[read], nums[write]];
      write++;
    }
  }
  return nums;
}
```

O(n) времени, O(1) памяти — именно это и проверяют (решение через `filter` и `concat`
создаёт новые массивы).

## Слияние отсортированных массивов

```js
function mergeSorted(a, b) {
  const result = [];
  let i = 0;
  let j = 0;
  while (i < a.length && j < b.length) {
    result.push(a[i] <= b[j] ? a[i++] : b[j++]);
  }
  while (i < a.length) result.push(a[i++]);
  while (j < b.length) result.push(b[j++]);
  return result;
}
```

O(n + m) — основа merge sort. `[...a, ...b].sort()` — O((n+m) log(n+m)) и к тому же
сортирует числа как строки без компаратора.

## Когда два указателя не работают

- Вход **не отсортирован**, а сортировка ломает условие задачи (нужны исходные индексы —
  в Two Sum по несортированному массиву лучше Map).
- Нужны **все** пары/подмножества — перебор неизбежен.
- Условие не монотонно: нельзя понять, какой указатель двигать, по текущему значению
  (например, произведение с отрицательными числами без дополнительного анализа).
- Задача про **непрерывный подотрезок** с условием — это уже sliding window
  (частный случай двух указателей с поддержкой состояния окна).

## Как это спрашивают

- «Найдите пару с суммой в отсортированном массиве без дополнительной памяти».
- «Проверьте палиндром», «разверните массив на месте».
- «Удалите дубли / переместите нули на месте за O(1) памяти».
- «Слейте два отсортированных массива».
- «Как найти середину связного списка за один проход? Как обнаружить цикл?»
