# memo, useMemo, useCallback

## Три инструмента — три объекта мемоизации

| Инструмент | Что мемоизирует | Когда пересчитывает |
| --- | --- | --- |
| `React.memo(Component)` | результат рендера компонента | когда хотя бы один проп изменился по `Object.is` |
| `useMemo(() => value, deps)` | значение | когда изменилась зависимость |
| `useCallback(fn, deps)` | функцию (ссылку) | когда изменилась зависимость |

`useCallback(fn, deps)` — это `useMemo(() => fn, deps)`.

## React.memo и поверхностное сравнение

```jsx
const Row = memo(function Row({ item, onSelect }) {
  return <li onClick={() => onSelect(item.id)}>{item.title}</li>;
});
```

При ререндере родителя React сравнит каждый проп `Row` с прошлым через `Object.is`.
Все равны — рендер пропускается. Вторым аргументом можно передать свою функцию
сравнения `(prev, next) => boolean`.

## Почему мемоизация ломается одним объектом

```jsx
function List({ items }) {
  const [selected, setSelected] = useState(null);
  return items.map((item) => (
    <Row
      key={item.id}
      item={item}
      style={{ padding: 8 }}                // новый объект каждый рендер
      onSelect={(id) => setSelected(id)}    // новая функция каждый рендер
    />
  ));
}
```

`memo` бесполезен: `style` и `onSelect` — новые ссылки на каждом рендере. Сравнение
пропсов выполняется, находит различие — и компонент рендерится. Мы заплатили за
сравнение и ничего не выиграли.

Исправления:

```jsx
const ROW_STYLE = { padding: 8 };                            // константа вне компонента
const handleSelect = useCallback((id) => setSelected(id), []); // стабильная функция
// или просто onSelect={setSelected} — сеттер из useState стабилен
```

То же касается `children`: JSX-элемент — новый объект на каждый рендер, поэтому
`memo`-компонент с `children` почти всегда перерисовывается.

## useMemo: когда он реально нужен

1. **Дорогое вычисление**, а компонент часто перерисовывается по другим причинам:
   фильтрация и сортировка тысяч элементов, построение графа, парсинг.
2. **Стабильность ссылки**, от которой что-то зависит:
   - объект/массив передаётся в `memo`-компонент;
   - значение в зависимостях `useEffect` (иначе эффект срабатывает каждый рендер);
   - `value` провайдера контекста.

Когда не нужен: сложение чисел, форматирование строки, маленькие массивы. Проверка
зависимостей и хранение значения стоят дороже самого вычисления.

«Дорогое» — это измеримо: оберните вычисление в `console.time` или посмотрите
Profiler. Ориентир из документации React — больше 1 мс.

## useCallback и стабильность ссылок

`useCallback` полезен **только** если стабильность функции кому-то нужна:

- функция передаётся в `memo`-компонент;
- функция — зависимость эффекта или другого хука;
- функция возвращается из кастомного хука (её потребители положат её в зависимости).

Обернуть обработчик обычной `<button>` в `useCallback` — бессмысленно: `<button>` не `memo`.

Главная ловушка — stale closure при неполных зависимостях:

```jsx
const add = useCallback((item) => setItems([...items, item]), []); // items навсегда []
const add = useCallback((item) => setItems((prev) => [...prev, item]), []); // правильно
```

## Структурные оптимизации — сначала

Прежде чем расставлять `memo`, посмотрите на структуру:

- **опустите state вниз** — если state нужен только поиску, пусть он живёт в компоненте
  поиска, а не в странице;
- **передайте тяжёлое поддерево как `children`** — оно создано в родителе и не
  перерисуется при изменении state обёртки;
- **разделите компонент** так, чтобы часто меняющаяся часть была отдельно.

## Цена мемоизации и React Compiler

Мемоизация — не бесплатна: память под значения, сравнение зависимостей на каждом рендере,
код сложнее читать, риск stale closure. Поэтому правило: **сначала измерить**
(React DevTools Profiler, «Why did this render?»), потом оптимизировать узкое место.

**React Compiler** (стабилен с 2025 года, работает с React 17+) анализирует код при сборке
и автоматически мемоизирует компоненты, значения и функции там, где это безопасно.
С ним ручные `memo`/`useMemo`/`useCallback` нужны редко. Условие — код следует правилам
React: чистый рендер, иммутабельные пропсы и state, хуки по правилам.
