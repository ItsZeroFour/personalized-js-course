# Сортировки и бинарный поиск

## Array.prototype.sort: три ловушки

```js
[10, 9, 1, 100].sort();                 // [1, 10, 100, 9] — строковое сравнение
[10, 9, 1, 100].sort((a, b) => a - b);  // [1, 9, 10, 100]
```

1. **Без компаратора элементы сравниваются как строки** (по UTF-16 кодам).
2. **Сортировка на месте**: метод мутирует массив и возвращает его же. Копия —
   `[...arr].sort(fn)` или `arr.toSorted(fn)` (ES2023).
3. **Компаратор** должен вернуть отрицательное число (a раньше), положительное (b раньше)
   или 0. Возврат `boolean` (`(a, b) => a > b`) — ошибка: `false` → 0, порядок ломается.

V8 использует **TimSort**: O(n log n) в худшем случае, O(n) на почти отсортированных
данных. Сортировка **стабильна** (гарантия с ES2019): равные элементы сохраняют
исходный порядок.

## Сортировка строк и объектов по нескольким полям

```js
users.sort(
  (a, b) =>
    a.city.localeCompare(b.city, 'ru') ||  // по городу А→Я
    b.age - a.age ||                        // затем по возрасту убывая
    a.name.localeCompare(b.name, 'ru'),
);
```

- Строки — через `localeCompare`: учитывает язык (`ё`, регистр); вычитать строки нельзя.
- `||` переходит к следующему критерию, только если предыдущий дал 0.
- Для большого числа сравнений — `new Intl.Collator('ru').compare` (быстрее).
- Стабильность позволяет сортировать последовательно по разным ключам.

## Бинарный поиск

Условие — **отсортированные** данные. Каждый шаг отбрасывает половину → O(log n).

```js
function binarySearch(sorted, target) {
  let left = 0;
  let right = sorted.length - 1;          // включительно
  while (left <= right) {
    const mid = left + ((right - left) >> 1);
    if (sorted[mid] === target) return mid;
    if (sorted[mid] < target) left = mid + 1;
    else right = mid - 1;
  }
  return -1;
}
```

## Типичные off-by-one

- Граница **включительная** (`right = n - 1`, `while (left <= right)`) или **исключительная**
  (`right = n`, `while (left < right)`, `right = mid`). Смешивать нельзя.
- `left = mid` без `+1` при `left < right` — бесконечный цикл, когда `right = left + 1`.
- Середина: `(left + right) >> 1` на огромных индексах в других языках переполняется;
  `left + ((right - left) >> 1)` — безопасная привычка.

Вариация, которую просят чаще точного поиска, — **первая позиция, где условие истинно**
(lower bound):

```js
function lowerBound(sorted, target) {
  let left = 0;
  let right = sorted.length;              // исключительно
  while (left < right) {
    const mid = (left + right) >> 1;
    if (sorted[mid] < target) left = mid + 1;
    else right = mid;
  }
  return left;                            // куда вставить target, сохранив порядок
}
```

Бинарный поиск работает не только по массиву, но и **по ответу**: «минимальная скорость,
чтобы успеть за h часов» — проверяем кандидата за O(n), кандидатов перебираем бинарно.

## Merge sort и quick sort на пальцах

**Merge sort**: разделить пополам, рекурсивно отсортировать половины, **слить** два
отсортированных массива двумя указателями. Всегда O(n log n), стабильна, требует O(n) памяти.

```js
function mergeSort(items) {
  if (items.length <= 1) return items;
  const mid = items.length >> 1;
  const left = mergeSort(items.slice(0, mid));
  const right = mergeSort(items.slice(mid));
  const result = [];
  let i = 0;
  let j = 0;
  while (i < left.length && j < right.length) result.push(left[i] <= right[j] ? left[i++] : right[j++]);
  return result.concat(left.slice(i), right.slice(j));
}
```

**Quick sort**: выбрать опорный элемент, разложить на «меньше» и «больше», рекурсивно
отсортировать части. В среднем O(n log n), в худшем O(n²) (плохой выбор опоры на уже
отсортированных данных), сортирует на месте, нестабильна.

## Поиск в почти отсортированных данных

- **Отсортированный, но сдвинутый** массив (`[4, 5, 6, 1, 2, 3]`): бинарный поиск, на
  каждом шаге одна из половин отсортирована — определяем какая и лежит ли target в ней.
- **Почти отсортированный** (элементы не дальше k от своих мест): insertion sort — O(n·k),
  TimSort тоже справляется быстро.
- Часто проще признать: «отсортирую за O(n log n) и найду бинарным поиском», если запросов много.

## Как это спрашивают

- «Почему `[10, 9, 1].sort()` даёт `[1, 10, 9]`?», «мутирует ли sort?»
- «Отсортируйте пользователей по городу, затем по возрасту».
- «Напишите бинарный поиск» — ждут отсутствие off-by-one и сложность.
- «Найдите первую позицию, куда можно вставить элемент».
- «Как работает merge sort? Какая сложность и почему?»
