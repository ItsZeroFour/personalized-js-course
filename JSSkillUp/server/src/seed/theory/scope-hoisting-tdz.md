# Область видимости, hoisting, TDZ

## Lexical environment: что это на самом деле

Каждый раз, когда движок входит в функцию или блок, он создаёт **Lexical Environment** —
структуру из двух частей:

- **Environment Record** — хранилище «имя → значение» для этой области;
- **ссылка на внешнее окружение** (`[[OuterEnv]]`).

Поиск переменной идёт по этой цепочке наружу до глобального окружения. Не найдено —
`ReferenceError`. Важно: цепочка строится **по месту объявления в коде** (лексически),
а не по месту вызова. Это ключевое отличие от `this`, который определяется в момент вызова.

## Две фазы: создание и исполнение

Перед исполнением кода функции движок проходит её и регистрирует объявления.
Это и называют hoisting — но «поднятия кода наверх» не происходит,
просто имена попадают в Environment Record заранее.

```js
console.log(a); // undefined  — var уже объявлена, но ещё не присвоена
console.log(f); // [Function: f] — объявление функции доступно целиком
console.log(b); // ReferenceError: Cannot access 'b' before initialization

var a = 1;
function f() {}
let b = 2;
```

Разница по типам объявлений:

| Объявление | Регистрируется заранее | Инициализируется | Область |
| --- | --- | --- | --- |
| `var` | да | сразу как `undefined` | функция |
| `function` | да | сразу телом функции | блок (в strict) / функция |
| `let` / `const` | да | только в точке объявления | блок |
| `class` | да | только в точке объявления | блок |

## TDZ — Temporal Dead Zone

`let` и `const` тоже поднимаются, но остаются **неинициализированными** от начала блока
до строки с объявлением. Обращение в этом промежутке — `ReferenceError`.

```js
{
  // здесь начинается TDZ для x
  typeof x; // ReferenceError — даже typeof не спасает
  let x = 1;
  // TDZ закончилась
}
```

Это сделано осознанно: TDZ превращает «тихий» `undefined` в громкую ошибку.
Показательный случай:

```js
let value = 'внешнее';
{
  console.log(value); // ReferenceError, а не 'внешнее'
  let value = 'внутреннее';
}
```

Внутренняя `value` уже занимает имя в блоке, поэтому наружу поиск не уходит.

## Function declaration против function expression

```js
hoisted();    // работает
notHoisted(); // TypeError: notHoisted is not a function

function hoisted() {}
var notHoisted = function () {};
```

`var notHoisted` поднялась как `undefined`, а `undefined()` — это `TypeError`, не `ReferenceError`.
Разница в тексте ошибки — типичный уточняющий вопрос на собеседовании.

## Блочная область и классический цикл

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i)); // 3, 3, 3
}

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i)); // 0, 1, 2
}
```

С `var` переменная одна на всю функцию — к моменту срабатывания таймеров цикл давно
закончился и `i === 3`. С `let` спецификация создаёт **новое** привязывание `i` на каждой
итерации и копирует в него значение предыдущей — поэтому каждое замыкание видит свою копию.

До ES6 это чинили через IIFE:

```js
for (var i = 0; i < 3; i++) {
  (function (j) {
    setTimeout(() => console.log(j));
  })(i);
}
```

## Глобальная область и var

```js
var g = 1;
let l = 2;

console.log(globalThis.g); // 1      — var создаёт свойство глобального объекта
console.log(globalThis.l); // undefined — let живёт в отдельной записи
```

В модулях (`type="module"`, ESM) верхний уровень — **не** глобальная область, а область модуля,
и `var` на верхнем уровне модуля свойства `globalThis` не создаёт.

## Функции внутри блоков

```js
{
  function inBlock() {}
}
typeof inBlock; // 'function' в sloppy mode, 'undefined' в strict mode
```

В strict mode (а модули всегда strict) объявление функции ограничено блоком.
В нестрогом режиме работает legacy web compatibility semantics, из-за которой имя
«протекает» в функциональную область. На собеседовании достаточно сказать:
в strict-режиме и в модулях function declaration блочно-областная.

## Как это спрашивают

- «Что такое hoisting?» — ждут объяснения через фазу создания контекста, а не метафору
  «код поднимается наверх».
- «Чем `let` отличается от `var`?» — область, TDZ, отсутствие свойства на `globalThis`,
  запрет повторного объявления, поведение в цикле.
- «Что выведет цикл с `var` и `setTimeout`?» — классика, ждут и ответ, и объяснение
  через одно общее привязывание.
- «Поднимается ли `let`?» — да, поднимается, но не инициализируется; в этом и есть TDZ.
- «Почему `typeof x` бросает ошибку в TDZ, хотя для необъявленной переменной не бросает?» —
  необъявленная переменная не найдена в цепочке вообще, а переменная в TDZ найдена,
  но помечена как неинициализированная.
