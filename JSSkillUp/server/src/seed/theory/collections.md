# Map, Set, WeakMap, WeakSet

## Map против объекта

```js
const map = new Map([
  ['a', 1],
  ['b', 2],
]);

map.set('c', 3);
map.get('a');       // 1
map.has('a');       // true
map.delete('a');
map.size;           // 2 — свойство, а не метод
map.clear();
```

Что даёт `Map` по сравнению с `{}`:

| | `Map` | Объект |
| --- | --- | --- |
| Ключи | любой тип, включая объекты и `NaN` | строки и символы |
| Порядок | гарантирован — порядок вставки | целые индексы вперёд |
| Размер | `.size` | `Object.keys(o).length` — O(n) |
| Итерация | встроенная, iterable | через `Object.keys/entries` |
| Прототип | нет лишних ключей | `toString`, `__proto__` и риск коллизий |
| Производительность | оптимизирован под частые вставки и удаления | оптимизирован под фиксированную форму |

Пример, ради которого `Map` и появился:

```js
const objKey = { id: 1 };
const obj = {};
obj[objKey] = 'значение';
Object.keys(obj);        // ['[object Object]'] — ключ превратился в строку

const map = new Map();
map.set(objKey, 'значение');
map.get(objKey);         // 'значение' — ключ сравнивается по идентичности
map.get({ id: 1 });      // undefined — другой объект
```

Когда всё же брать объект: фиксированный набор известных ключей, нужен JSON
(`Map` не сериализуется в `JSON.stringify` — даст `{}`), нужен удобный доступ через точку.

## Сравнение ключей

`Map` и `Set` используют алгоритм SameValueZero: как `===`, но `NaN` равен `NaN`,
а `+0` и `-0` считаются одним значением.

```js
const set = new Set([NaN, NaN, 0, -0]);
set.size; // 2 — один NaN и один ноль
```

## Итерация

```js
for (const [key, value] of map) {}
map.forEach((value, key) => {});   // порядок аргументов обратный привычному

[...map.keys()];
[...map.values()];
[...map.entries()];
```

Конвертация:

```js
const obj = Object.fromEntries(map);        // Map → объект (ключи станут строками)
const map = new Map(Object.entries(obj));   // объект → Map
```

## Set

```js
const set = new Set([1, 2, 2, 3]);
set.size;          // 3
set.add(4);
set.has(2);        // true, O(1)
set.delete(2);
[...set];          // массив обратно
```

Классические применения:

```js
const unique = [...new Set(array)];                       // дедупликация примитивов

const a = new Set([1, 2, 3]);
const b = new Set([2, 3, 4]);
const intersection = [...a].filter((x) => b.has(x));      // [2, 3]
const difference = [...a].filter((x) => !b.has(x));       // [1]
const union = new Set([...a, ...b]);
```

В новых движках появились методы множеств: `a.intersection(b)`, `a.union(b)`,
`a.difference(b)`, `a.isSubsetOf(b)`.

Важно: дедупликация через `Set` работает только для примитивов. Объекты сравниваются
по ссылке, поэтому для них нужен ключ:

```js
const uniqueById = [...new Map(users.map((u) => [u.id, u])).values()];
```

## Почему Set быстрее массива

`includes` и `indexOf` у массива — линейный поиск O(n). У `Set` и `Map` — хеш-таблица,
доступ в среднем O(1).

```js
// O(n²) — на каждом элементе линейный поиск
const dupes = arr.filter((x, i) => arr.indexOf(x) !== i);

// O(n)
const seen = new Set();
const dupes = arr.filter((x) => (seen.has(x) ? true : (seen.add(x), false)));
```

Это тот самый приём «обменять память на скорость», который ждут в алгоритмических задачах.

## WeakMap и WeakSet

Держат ключи **слабо**: объект в такой коллекции может быть собран сборщиком мусора.

Ограничения (они же — ответ на «почему»):

- ключи только объекты и незарегистрированные символы;
- нет `size`, нет итерации, нет `clear`;
- нельзя посмотреть содержимое.

Причина одна: иначе через коллекцию можно было бы **наблюдать за работой GC**, а момент
сборки недетерминирован — программа стала бы зависеть от внутренних деталей движка.

Применения:

```js
// метаданные, привязанные ко времени жизни DOM-узла
const listeners = new WeakMap();
listeners.set(element, handler);
// элемент удалён из DOM и недостижим → запись исчезнет сама

// приватные данные экземпляров (до появления #private)
const privates = new WeakMap();
class Counter {
  constructor() {
    privates.set(this, { count: 0 });
  }
  inc() {
    privates.get(this).count += 1;
  }
}

// кеш результатов по объекту-аргументу, не мешающий сборке
const cache = new WeakMap();
function compute(obj) {
  if (cache.has(obj)) return cache.get(obj);
  const result = expensive(obj);
  cache.set(obj, result);
  return result;
}
```

Обычный `Map` в роли такого кеша — гарантированная утечка памяти: он держит ключи сильно.

## Что выбрать

- **Объект** — конфигурация, DTO, всё, что уходит в JSON.
- **Map** — динамический словарь, ключи-объекты, важен порядок, много вставок и удалений.
- **Set** — уникальность и быстрая проверка вхождения.
- **WeakMap/WeakSet** — данные, привязанные к чужому объекту, время жизни которого
  вы не контролируете.

## Как это спрашивают

- «Чем `Map` отличается от объекта?» — ключи, порядок, размер, итерируемость, прототип.
- «Как удалить дубликаты из массива?» — `Set`, а для объектов — `Map` по ключу.
- «Зачем `WeakMap`, если есть `Map`?» — слабые ссылки, утечки, пример с DOM.
- «Почему `WeakMap` нельзя итерировать?» — иначе наблюдаемо поведение GC.
- «Что быстрее: `array.includes` или `set.has`?» — O(n) против O(1),
  и когда разница не важна (маленькие массивы).
