# Сложность алгоритмов, Big O

## Что описывает Big O

Big O отвечает на вопрос: **как растёт время (или память) при росте входа**.
Не «сколько миллисекунд», а «во сколько раз медленнее, если данных станет в 10 раз больше».

Правила упрощения:

- **константы отбрасываются**: `2n` → O(n), `n/2` → O(n);
- **младшие члены отбрасываются**: `n² + 100n + 5` → O(n²);
- **разные входы — разные буквы**: два массива → O(n + m) или O(n · m), не O(n²);
- по умолчанию говорят о **худшем случае**.

## Основные классы

| Класс | Пример | n = 1 000 | n = 1 000 000 |
| --- | --- | --- | --- |
| O(1) | доступ `arr[i]`, `map.get(key)` | 1 | 1 |
| O(log n) | бинарный поиск | ~10 | ~20 |
| O(n) | один проход по массиву | 1 000 | 1 000 000 |
| O(n log n) | хорошая сортировка | ~10 000 | ~20 000 000 |
| O(n²) | вложенные циклы по одному массиву | 1 000 000 | 10¹² — не дождаться |
| O(2ⁿ) | перебор подмножеств | — | — |

```js
// O(n): один проход
function max(items) {
  let best = -Infinity;
  for (const x of items) if (x > best) best = x;
  return best;
}

// O(n²): каждый с каждым
function hasDuplicate(items) {
  for (let i = 0; i < items.length; i++)
    for (let j = i + 1; j < items.length; j++)
      if (items[i] === items[j]) return true;
  return false;
}

// O(n) времени, O(n) памяти: обмен памяти на скорость
function hasDuplicateFast(items) {
  return new Set(items).size !== items.length;
}
```

**O(log n)** появляется, когда на каждом шаге задача **делится пополам**: бинарный поиск,
сбалансированное дерево, «сколько раз можно разделить n на 2».

## Сложность по памяти

Считается **дополнительная** память, помимо входа:

- новый массив/Map на n элементов — O(n);
- несколько переменных — O(1);
- **рекурсия глубины d — O(d)** из-за стека вызовов, даже если структуры не создаются.

Частый компромисс интервью: «можно O(n²) времени и O(1) памяти или O(n) времени и O(n)
памяти». Обычно выбирают второе — память дешевле времени, — но надо проговорить.

## Амортизированная сложность

`push` в массив иногда стоит O(n): закончилась ёмкость, и движок копирует элементы
в новый, вдвое больший буфер. Но это происходит всё реже (при 1, 2, 4, 8, … элементах),
и **суммарно** n вставок стоят O(n). Средняя стоимость одной — **O(1) амортизированно**.

То же у `Map.set` / `Set.add`: хеш-таблица периодически перестраивается, но в среднем O(1).

## Сложность встроенных методов JS

| Операция | Сложность |
| --- | --- |
| `arr[i]`, `arr.length`, `push`, `pop` | O(1) |
| `shift`, `unshift`, `splice` в начале/середине | O(n) — сдвиг элементов |
| `includes`, `indexOf`, `find`, `some`, `filter`, `map`, `reduce` | O(n) |
| `slice`, `concat`, `[...arr]` | O(k) — размер копии |
| `sort` | O(n log n) |
| `Map`/`Set`: `get`, `set`, `has`, `delete` | O(1) в среднем |
| `Object.keys`, `Object.entries` | O(n) — число ключей |
| `str.split`, `str.includes`, конкатенация | O(длины строки) |

Главная скрытая ловушка — **линейный метод внутри цикла**:

```js
// O(n · m): includes каждый раз проходит весь массив
const common = a.filter((x) => b.includes(x));

// O(n + m)
const bSet = new Set(b);
const common2 = a.filter((x) => bSet.has(x));
```

То же с `indexOf` в `filter` для дедупликации, `find` в `map` для join двух массивов,
`shift` в очереди BFS.

## Как проговаривать оценку на интервью

1. Сначала решение «в лоб» и его сложность: «перебор пар — O(n²)».
2. Где узкое место: «повторный поиск по массиву».
3. Оптимизация и цена: «храню увиденное в Set — O(n) времени, O(n) памяти».
4. Граничные случаи: пустой вход, один элемент, дубли, отрицательные числа.
5. Если спросят «можно ли лучше» — подумайте о нижней границе: чтобы найти
   максимум, нужно посмотреть на каждый элемент, значит меньше O(n) невозможно.

## Как это спрашивают

- «Какая сложность у вашего решения?» — после каждой задачи live-coding.
- «Можно ли быстрее? А по памяти?»
- «Какая сложность у `includes` / `shift` / `sort`?»
- «Почему `push` O(1), если массив иногда копируется?» — амортизация.
- «Сколько памяти использует рекурсивное решение?» — стек.
