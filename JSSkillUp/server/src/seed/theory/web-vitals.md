# Web Vitals и производительность

## Core Web Vitals

| Метрика | Что измеряет | Хорошо | Плохо |
| --- | --- | --- | --- |
| **LCP** — Largest Contentful Paint | когда отрисован самый большой видимый элемент (картинка, блок текста) | ≤ 2,5 с | > 4 с |
| **INP** — Interaction to Next Paint | задержка от взаимодействия (клик, нажатие) до следующего кадра, по худшим взаимодействиям за визит | ≤ 200 мс | > 500 мс |
| **CLS** — Cumulative Layout Shift | сумма неожиданных сдвигов вёрстки | ≤ 0,1 | > 0,25 |

INP заменил FID в марте 2024: FID учитывал только **первое** взаимодействие и только
задержку до начала обработки, INP — все взаимодействия и полное время до отрисовки.

Вспомогательные метрики: TTFB (время до первого байта), FCP (первая отрисовка контента),
TBT (суммарное время блокировки main thread в лаборатории).

**Полевые** данные (реальные пользователи: библиотека `web-vitals`, CrUX, RUM) важнее
**лабораторных** (Lighthouse): лаборатория — одно устройство и одна сеть.

## LCP: причины и решения

- медленный сервер (TTFB) → кеш, CDN, SSR/SSG;
- LCP-картинка **обнаруживается поздно**: её вставляет JS, она в CSS `background`,
  у неё `loading="lazy"` → обычный `<img>` в HTML, `fetchpriority="high"`, `preload`;
  lazy — только для того, что ниже первого экрана;
- тяжёлое изображение → AVIF/WebP, `srcset` и `sizes`, правильные размеры, CDN с ресайзом;
- блокирующие CSS и JS, весь контент рендерится на клиенте → критический CSS, `defer`,
  SSR, код-сплиттинг;
- текст ждёт веб-шрифт → `font-display: swap`, `preload` шрифта.

## CLS: причины и решения

- картинки, видео, iframe **без размеров** → `width`/`height` атрибуты или `aspect-ratio`;
- контент вставляется **над** существующим (баннеры, реклама, уведомления) → резервировать
  место или показывать поверх;
- смена шрифта меняет метрики текста → `size-adjust`, похожий системный fallback;
- скелетоны другого размера, чем итоговый контент;
- анимации через `top`/`height` вместо `transform`.

Сдвиги в течение 500 мс после действия пользователя не считаются — ожидаемые.

## Long tasks и отзывчивость (INP)

**Long task** — задача на main thread дольше 50 мс. Пока она выполняется, браузер не
обрабатывает ввод и не рисует кадры. INP страдает от:

- тяжёлых обработчиков событий (синхронная фильтрация 10 000 строк на каждый ввод);
- большого ререндера React на каждое нажатие;
- лишнего JS: гидрация, сторонние скрипты, аналитика.

Решения:

- **дробить** работу: `await scheduler.yield()` (или `setTimeout(0)`) между частями;
- переносить вычисления в **Web Worker**;
- в React — `useTransition`/`useDeferredValue`: срочное обновление поля, тяжёлый рендер
  в прерываемом фоне;
- debounce для дорогой реакции на ввод;
- меньше JS на странице.

## React Profiler и лишние ререндеры

React DevTools → Profiler: записать сессию и посмотреть, какие компоненты рендерились,
сколько времени заняли и **почему** (опция «Record why each component rendered»).
Highlight updates подсвечивает перерисовки на странице.

Типичные находки: state слишком высоко, новый объект в `value` контекста, стрелки в пропсах
`memo`-компонентов, производное состояние через эффект (лишний рендер).

## Виртуализация длинных списков

10 000 строк в DOM — медленный первый рендер, тяжёлый layout, память. Виртуализация
рендерит только видимые строки + небольшой запас, а высоту прокрутки имитирует:

```jsx
const virtualizer = useVirtualizer({
  count: rows.length,
  getScrollElement: () => parentRef.current,
  estimateSize: () => 36,
});
```

Библиотеки: `@tanstack/react-virtual`, `react-window`, `react-virtuoso`. Для простых
случаев — CSS `content-visibility: auto`: браузер пропускает рендеринг вне экрана.

## Изображения и шрифты

- Форматы AVIF/WebP, `srcset` + `sizes` под размер экрана, `loading="lazy"` и
  `decoding="async"` ниже первого экрана.
- Всегда размеры или `aspect-ratio` — против CLS.
- Шрифты: WOFF2, подмножество символов (кириллица + латиница), `preload` основного
  начертания, `font-display: swap` или `optional`.
