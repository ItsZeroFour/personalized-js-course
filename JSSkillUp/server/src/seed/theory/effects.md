# useEffect, useLayoutEffect, cleanup

## Для чего эффекты

Эффект — это **синхронизация компонента с внешней системой**: подписка на события
окна, WebSocket, таймер, сторонняя библиотека (карта, график), запрос к серверу,
ручная работа с DOM. Код эффекта выполняется, потому что компонент **показан**,
а не потому что пользователь что-то сделал.

## Порядок выполнения

```
render → commit (DOM обновлён, ref заполнены) → useLayoutEffect → браузер рисует кадр → useEffect
```

- **`useLayoutEffect`** — синхронно после изменения DOM, **до** отрисовки. Нужен, когда
  надо измерить элемент и сразу скорректировать (позиция тултипа, скролл), чтобы
  пользователь не увидел промежуточный кадр. Блокирует отрисовку — использовать точечно.
- **`useEffect`** — после отрисовки, не блокирует кадр. Выбор по умолчанию.

Эффекты детей выполняются раньше эффектов родителя.

## Зависимости

```jsx
useEffect(() => { … });            // после каждого рендера
useEffect(() => { … }, []);        // один раз после монтирования
useEffect(() => { … }, [userId]);  // когда изменился userId (Object.is)
```

Правило: **в зависимостях всё, что эффект читает из рендера** — пропсы, state, функции
и значения, объявленные в компоненте. Это проверяет `react-hooks/exhaustive-deps`.
Неполные зависимости = stale closure: эффект работает со старыми значениями.

Если зависимость «мешает» (эффект срабатывает слишком часто), нужно менять код,
а не выкидывать её из массива:

- объект/функцию, не зависящие от рендера, вынести из компонента;
- функцию, нужную только эффекту, объявить внутри эффекта;
- объект из примитивов — зависеть от примитивов (`options.page`, а не `options`);
- «прочитать свежее значение, не реагируя на него» — ref или `useEffectEvent`.

## Cleanup

Функция, возвращённая из эффекта, вызывается:

- **перед следующим запуском** эффекта (со значениями прошлого рендера);
- **при размонтировании**.

```jsx
useEffect(() => {
  const onResize = () => setWidth(window.innerWidth);
  window.addEventListener('resize', onResize);
  return () => window.removeEventListener('resize', onResize);
}, []);
```

Правило: cleanup должен **полностью отменять** то, что сделал эффект — отписка,
`clearInterval`, закрытие соединения, отмена запроса.

## StrictMode и двойной эффект

В режиме разработки StrictMode при монтировании выполняет «эффект → cleanup → эффект».
Если после этого поведение отличается от одиночного запуска — cleanup неполный.
Классический пример — два WebSocket-соединения или двойная подписка. Это проверка,
а не баг; в production двойного вызова нет.

## Гонки запросов

```jsx
useEffect(() => {
  let ignore = false;
  fetchUser(userId).then((user) => {
    if (!ignore) setUser(user);
  });
  return () => {
    ignore = true;
  };
}, [userId]);
```

Пользователь быстро переключил `userId`: 1 → 2. Если ответ по 1 придёт позже, без флага
на экране окажется не тот пользователь. Флаг `ignore` отбрасывает устаревший ответ;
`AbortController` вдобавок отменяет сам запрос:

```jsx
useEffect(() => {
  const controller = new AbortController();
  fetch(`/api/users/${userId}`, { signal: controller.signal })
    .then((r) => r.json())
    .then(setUser)
    .catch((error) => {
      if (!controller.signal.aborted) setError(error);
    });
  return () => controller.abort();
}, [userId]);
```

На практике загрузку данных лучше отдать TanStack Query или фреймворку — кеш, гонки,
повторы уже решены.

## Когда эффект не нужен

1. **Производные данные** — считать при рендере:
   `const fullName = first + ' ' + last`, а не `useEffect` + `setFullName`.
2. **Реакция на действие пользователя** — в обработчике: отправка формы, аналитика клика,
   уведомление.
3. **Сброс state при смене пропса** — `key` на компоненте.
4. **Цепочки эффектов** (эффект ставит state → срабатывает другой эффект) — вычислить
   всё в одном обработчике.
5. **Уведомить родителя об изменении** — вызвать `onChange` там же, где меняется state.
6. **Инициализация приложения один раз** — код на уровне модуля или флаг вне компонента.

Критерий: код нужен, потому что компонент **появился на экране** → эффект. Потому что
пользователь **что-то сделал** → обработчик.

## Как это спрашивают

- «В каком порядке выполняются эффекты и cleanup?» — часто с задачей «что в консоли».
- «Чем `useLayoutEffect` отличается от `useEffect`?»
- «Почему эффект вызывается дважды в разработке?»
- «Как избежать гонки при загрузке данных в эффекте?»
- «Приведите примеры, когда `useEffect` не нужен» — хороший маркер уровня.
