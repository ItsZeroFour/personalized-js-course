# Типы данных и приведение типов

## Что нужно держать в голове

В JavaScript **8 типов**: семь примитивов (`number`, `string`, `boolean`, `null`, `undefined`,
`symbol`, `bigint`) и `object`. Всё остальное — функции, массивы, даты, регулярки — это объекты.

Примитивы **иммутабельны**. `str[0] = 'X'` молча не сработает (в strict mode — бросит `TypeError`).
Любая «мутация» строки на самом деле создаёт новую строку.

## Автобоксинг: почему у примитива есть методы

```js
const s = 'привет';
console.log(s.toUpperCase()); // ПРИВЕТ
```

У примитива нет методов. При обращении к свойству движок временно оборачивает значение
в объект-обёртку (`new String(s)`), берёт метод из `String.prototype`, вызывает его и
выбрасывает обёртку. Отсюда классика:

```js
const s = 'привет';
s.lang = 'ru';
console.log(s.lang); // undefined — свойство записалось во временную обёртку, которую уже собрал GC
```

Не путайте примитив и обёртку:

```js
typeof 'x';              // 'string'
typeof new String('x');  // 'object'
new String('') ? 'да' : 'нет'; // 'да' — любой объект truthy, даже обёртка пустой строки
```

## typeof, instanceof и надёжная проверка типа

```js
typeof null;        // 'object'  ← баг первой реализации, сохранён для обратной совместимости
typeof [];          // 'object'
typeof function(){}; // 'function'
typeof undeclared;   // 'undefined' — единственная операция, не бросающая ReferenceError
```

`instanceof` идёт по цепочке прототипов и ломается на границе realm (iframe, worker):
массив из другого окна не пройдёт `arr instanceof Array`. Поэтому:

```js
Array.isArray(value);                               // правильная проверка массива
Object.prototype.toString.call(value);              // '[object Date]', '[object Null]', ...
Number.isNaN(value);                                // без приведения, в отличие от глобального isNaN
```

## ToPrimitive: как объект превращается в примитив

Когда объект попадает в операцию, ждущую примитив, вызывается абстрактная операция
**ToPrimitive(input, hint)**. Hint бывает `"number"`, `"string"` и `"default"`.

Порядок:

1. Если есть `Symbol.toPrimitive` — вызывается он, и результат финальный.
2. Иначе для hint `"string"`: сначала `toString()`, потом `valueOf()`.
3. Для hint `"number"` и `"default"`: сначала `valueOf()`, потом `toString()`.

```js
const money = {
  amount: 100,
  [Symbol.toPrimitive](hint) {
    if (hint === 'number') return this.amount;
    if (hint === 'string') return `${this.amount} ₽`;
    return `Money(${this.amount})`;
  },
};

+money;        // 100          → hint 'number'
`${money}`;    // '100 ₽'      → hint 'string'
money + '';    // 'Money(100)' → hint 'default'
```

Отсюда знаменитое:

```js
[] + [];   // ''      — оба массива дают '' через toString
[] + {};   // '[object Object]'
{} + [];   // 0 в консоли: {} парсится как блок, остаётся унарный +[] → 0
```

Последнюю строку на собеседовании ждут именно с оговоркой «зависит от того, выражение это
или инструкция». `({}) + []` даёт `'[object Object]'`.

## Оператор + : сложение или конкатенация

`+` — единственный оператор, который умеет и то и другое. Правило: если после ToPrimitive
хотя бы один операнд — строка, будет конкатенация. Иначе оба приводятся к числу.

```js
1 + '2';       // '12'
1 + 2 + '3';   // '33'   — слева направо: (1+2) = 3, потом '3' + '3'
'1' + 2 + 3;   // '123'
1 - '2';       // -1     — минус всегда числовой
'5' * '2';     // 10
true + true;   // 2
null + 1;      // 1      — Number(null) === 0
undefined + 1; // NaN    — Number(undefined) === NaN
```

## == против ===

`===` сравнивает без приведения (с двумя исключениями: `NaN !== NaN`, а `+0 === -0`).

`==` запускает Abstract Equality Comparison. Важные шаги:

- `null == undefined` → `true`, и **больше ни с чем** они не равны;
- если типы разные и оба — не объекты, всё приводится к числу;
- объект сравнивается с примитивом через ToPrimitive.

```js
null == undefined;  // true
null == 0;          // false ← частая ловушка: null не приводится к числу в ==
null >= 0;          // true  ← а здесь приводится, потому что это уже другой алгоритм
'' == 0;            // true
'0' == 0;           // true
'' == '0';          // false
[] == false;        // true  → [] → '' → 0, false → 0
[1] == 1;           // true
NaN == NaN;         // false
```

Практическое правило: всегда `===`. Единственное оправданное исключение —
`value == null` как проверка «null или undefined одним выражением».

## NaN, -0 и Object.is

```js
NaN === NaN;            // false
Object.is(NaN, NaN);    // true
Number.isNaN(NaN);      // true
isNaN('привет');        // true  ← глобальная isNaN сначала приводит к числу
Number.isNaN('привет'); // false ← правильная проверка

0 === -0;               // true
Object.is(0, -0);       // false
1 / -0;                 // -Infinity — единственный практичный способ их различить
```

## Falsy-значения

Ровно восемь: `false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN`. Всё остальное truthy,
включая `[]`, `{}`, `'0'`, `'false'` и `function(){}`.

Отсюда разница операторов:

```js
const a = 0 || 'default';  // 'default' — || смотрит на truthy
const b = 0 ?? 'default';  // 0         — ?? смотрит только на null и undefined
```

Во фронтенде это реальный источник багов: `count || 10` подставит 10 при валидном нуле,
`count ?? 10` — нет.

## Как это спрашивают

- «Чем `==` отличается от `===`?» — ждут не «одно строгое, другое нет», а упоминания
  ToPrimitive и пары `null == undefined`.
- «Почему `typeof null === 'object'`?» — историческая ошибка, тег типа объекта был 0,
  а null был нулевым указателем.
- «Что вернёт `[] + {}` и `{} + []`?» — ждут разговора про ToPrimitive и про разбор
  `{}` как блока.
- «Как проверить, что перед вами массив?» — `Array.isArray`, с объяснением, почему
  `instanceof` не годится между realm.
- «В чём разница `||` и `??`?» — обязательно с примером, где 0 или пустая строка валидны.
