# Бандл и загрузка

## Почему размер JS важен

JS дороже картинки того же размера: его нужно **скачать, распарсить, скомпилировать и
выполнить**, и всё это на main thread. На среднем телефоне мегабайт JS — секунды до
интерактивности. Каждые лишние 100 КБ бьют по LCP и INP.

## Code splitting по роутам и компонентам

```jsx
const Settings = lazy(() => import('./pages/Settings'));
const Chart = lazy(() => import('./components/HeavyChart'));
```

Динамический `import()` — точка разделения: сборщик выносит модуль и его зависимости
в отдельный чанк, который загрузится при первом обращении.

Порядок работы:

1. **Маршруты** — пользователю не нужен код всех страниц сразу.
2. **Тяжёлые редкие компоненты**: редактор кода, графики, карты, модалки с формами.
3. **Библиотеки по требованию**: `const { jsPDF } = await import('jspdf')` в обработчике
   кнопки «Экспорт».

Не дробить до мелочи: каждый чанк — запрос, а общие зависимости сборщик и так выносит
в vendor-чанки.

## React.lazy и Suspense

`lazy` вызывают на уровне модуля; пока чанк грузится, ближайший `<Suspense>` показывает
fallback. Если загрузка упала (деплой удалил старые чанки, сеть) — ошибку ловит
error boundary; частый приём — перезагрузить страницу при `ChunkLoadError`.

Чтобы переход был мгновенным, чанк **предзагружают**: при наведении на ссылку вызвать
тот же `import()` (браузер закеширует модуль), или роутер делает это сам.

## preload, prefetch, preconnect

```html
<link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2" crossorigin>
<link rel="preconnect" href="https://api.example.com">
<link rel="prefetch" href="/assets/settings.js">
<link rel="modulepreload" href="/assets/app.js">
```

- **preload** — ресурс нужен на **этой** странице и скоро: высокий приоритет (шрифт,
  LCP-картинка, критический чанк). Лишний preload отнимает полосу у важного.
- **prefetch** — может понадобиться на **следующей** странице: низкий приоритет, в простое.
- **preconnect** — заранее установить соединение (DNS, TCP, TLS) с другим доменом.
- **modulepreload** — preload для ES-модулей (Vite добавляет сам).

## Tree shaking и sideEffects

Tree shaking — удаление неиспользуемых экспортов на этапе сборки. Условия:

- **ES-модули**: статические `import`/`export` анализируются; CommonJS (`require`) — почти нет;
- **импорт конкретного**: `import { debounce } from 'lodash-es'`, а не весь объект с
  динамическим доступом;
- **нет побочных эффектов** при импорте модуля; пакет сообщает это полем
  `"sideEffects": false` в `package.json` (или списком файлов со сторонними эффектами — CSS,
  полифилы).

Классические примеры: `lodash` (CJS, тянет всё) против `lodash-es` или отдельных
функций; иконки — импорт одной иконки, а не всего набора; `moment` с локалями против
`date-fns`/`dayjs`.

## Анализ размера бандла

- **`rollup-plugin-visualizer`** (Vite) / `webpack-bundle-analyzer` — карта бандла:
  что сколько весит;
- **`source-map-explorer`** — анализ по source maps;
- **bundlephobia.com** — сколько стоит пакет до установки;
- **size-limit** в CI — бюджет на размер, PR не пройдёт, если бандл вырос.

Что обычно находят: дубли одной библиотеки разных версий, полифилы для старых браузеров,
которые не нужны, целиком импортированные библиотеки, моки и dev-код в проде, огромные
JSON с данными.

## Прочее

- **Сжатие** на сервере: Brotli (лучше gzip на 15–20% для текста).
- **Современный таргет** сборки: не транспилировать `async`/классы для браузеров,
  которые их давно поддерживают.
- **Сторонние скрипты** (чаты, аналитика, пиксели) — `async`/`defer`, загрузка после
  взаимодействия, Partytown для выноса в воркер.
