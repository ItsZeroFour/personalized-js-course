# Память и garbage collection

## Достижимость

Сборщик мусора в JavaScript не считает ссылки — он ищет **достижимые** объекты.

Есть набор корней (roots): глобальный объект, текущий стек вызовов с локальными
переменными, замыкания живых функций. Объект жив, если до него есть путь от корня.
Всё остальное — мусор, даже если объекты ссылаются друг на друга.

```js
let a = { name: 'a' };
let b = { name: 'b' };
a.next = b;
b.prev = a;   // циклическая ссылка

a = null;
b = null;     // оба будут собраны: от корней до них пути нет
```

Именно поэтому в JS нет классической проблемы циклических ссылок, которая мучила
подсчёт ссылок в старых движках.

## Mark-and-sweep

Алгоритм в три шага: пометить корни → обойти все достижимые объекты и пометить их →
удалить непомеченные.

V8 усложняет это поколенческой сборкой:

- **Young generation (nursery)** — новые объекты. Собирается часто и быстро алгоритмом
  Scavenge: выжившие копируются, остальное отбрасывается целиком. Большинство объектов
  умирает молодыми.
- **Old generation** — пережившие пару сборок. Собирается редко, mark-sweep-compact,
  с инкрементальной и конкурентной пометкой, чтобы не останавливать поток надолго.

Практический вывод: создавать много короткоживущих объектов дёшево; держать много
долгоживущих — дорого.

## Типичные утечки во фронтенде

### Незакрытые таймеры

```js
const id = setInterval(() => {
  render(hugeState);      // держит hugeState навсегда
}, 1000);
// нет clearInterval(id) — утечка
```

### Неснятые слушатели

```js
window.addEventListener('resize', onResize);
// компонент размонтирован, слушатель остался и держит его замыкание
```

### Оторванный DOM (detached nodes)

```js
const node = document.getElementById('big-table');
document.body.removeChild(node);
// переменная node жива → весь узел с потомками остаётся в памяти
```

Это самый частый вид утечки в SPA: в devtools он виден в heap snapshot как
«Detached HTMLDivElement».

### Растущие кеши и глобальные коллекции

```js
const cache = new Map();
function get(user) {
  cache.set(user, expensive(user)); // никогда не чистится
}
```

### Замыкания

Замыкание держит окружение целиком. Если в нём лежит большой объект, он не будет собран,
пока жива функция.

## Weak-структуры

`WeakMap` и `WeakSet` держат ключи **слабо**: наличие объекта в такой коллекции
не мешает его сборке.

```js
const meta = new WeakMap();

function attach(element, data) {
  meta.set(element, data);
}
// элемент удалён из DOM и больше нигде не нужен → запись исчезнет сама
```

Ограничения: ключи только объекты (и незарегистрированные символы), коллекция
не итерируется и не имеет `size` — иначе по ней можно было бы наблюдать работу GC.

`WeakRef` и `FinalizationRegistry` — низкоуровневые инструменты для кешей;
в обычном приложении они почти не нужны, но знать об их существовании полезно:

```js
const ref = new WeakRef(bigObject);
const value = ref.deref(); // undefined, если объект уже собран
```

## Утечки в React

```jsx
useEffect(() => {
  const id = setInterval(tick, 1000);
  const controller = new AbortController();
  window.addEventListener('resize', onResize);

  fetch(url, { signal: controller.signal }).then(setData);

  return () => {
    clearInterval(id);
    window.removeEventListener('resize', onResize);
    controller.abort();
  };
}, []);
```

Правило: **всё, что подписывается, должно отписываться в cleanup**. Второй частый
случай — `setState` после размонтирования: сам по себе он больше не предупреждает
(React 18 убрал варнинг), но запрос, который никому не нужен, всё равно стоит отменять.

Третий — замыкания в подписках на внешний стор, которые держат старый стейт.

## Как искать утечки

1. DevTools → **Memory** → Heap snapshot: сделать снимок, выполнить сценарий
   (открыть-закрыть модалку 10 раз), сделать второй снимок, сравнить
   в режиме **Comparison**. Растущее число Detached-узлов или экземпляров компонента —
   утечка.
2. **Performance** → галочка Memory: график памяти с пилообразной формой — норма,
   монотонный рост — утечка.
3. **Allocation instrumentation on timeline** — показывает, какие аллокации выживают.

## Что ещё спрашивают про память

- **Стек и куча.** Примитивы и ссылки — в стеке кадра вызова, объекты — в куче.
  (В реальности V8 умеет размещать объекты в стеке при escape-анализе, но для собеседования
  базовой модели достаточно.)
- **Переполнение стека.** Глубокая рекурсия → `RangeError: Maximum call stack size exceeded`.
  Лечится переходом на цикл или явный стек. Хвостовая рекурсия в V8 не оптимизируется.
- **Можно ли вызвать GC вручную?** Нет. `delete obj.prop` удаляет свойство, а не объект,
  и замедляет доступ к объекту (меняет hidden class). Присваивание `null` просто убирает
  одну ссылку.

## Как это спрашивают

- «Как работает сборщик мусора?» — достижимость от корней, mark-and-sweep, поколения.
- «Соберётся ли объект с циклической ссылкой?» — да, если недостижим от корней.
- «Приведите пример утечки памяти в SPA» — таймер, слушатель, detached DOM.
- «Зачем нужен `WeakMap`?» — кеш и приватные данные, привязанные к времени жизни объекта.
- «Как найти утечку?» — heap snapshot и сравнение двух снимков.
