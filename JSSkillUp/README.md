# JSSkillUp

Локальное приложение для системной подготовки к собеседованию на **React Middle Developer**.
Роадмап с трекингом прогресса, теория, квизы, флеш-карточки с интервальным повторением,
практические задачи с автотестами в песочнице (JS/TS в Web Worker, React — с живым превью)
и mock interview с AI-интервьюером.

Всё работает локально: данные лежат в SQLite-файле рядом с проектом, наружу уходят только
запросы к Groq — и только с бэкенда.

Сейчас в базе: **9 этапов и 68 тем**, у каждой темы есть статья теории и флеш-карточки:
**68 статей, 165 вопросов, 267 карточек и 63 задачи с 323 автотестами** — 43 на логику
и алгоритмы, 14 React-задач с живым превью и 6 задач на code review.

## Требования

| Что | Версия | Комментарий |
| --- | --- | --- |
| Node.js | **≥ 22.5.0** | нужен встроенный модуль `node:sqlite` |
| npm | ≥ 10 | воркспейсы |

### Про флаг `--experimental-sqlite`

Модуль `node:sqlite` появился в Node 22.5.0 и до сих пор помечен как экспериментальный,
но флаг нужен не всегда:

| Версия Node | Нужен ли флаг |
| --- | --- |
| 22.5.0 – 23.3.x | **да**, запускать как `node --experimental-sqlite …` |
| ≥ 23.4.0 (включая 24.x) | **нет**, модуль доступен без флагов |

Проверить свою версию: `node -v`. Если она попадает в первый диапазон, добавьте флаг в
скрипты `server/package.json` (`tsx --experimental-sqlite watch …`).

## Установка

```bash
npm install
cp .env.example .env     # Windows: copy .env.example .env
```

### Ключ Groq

1. Зарегистрируйтесь на [console.groq.com](https://console.groq.com) — бесплатного тарифа хватает.
2. Создайте ключ: **API Keys → Create API Key**.
3. Вставьте его в `.env`:

```dotenv
GROQ_API_KEY=gsk_ваш_ключ
GROQ_MODEL=openai/gpt-oss-120b
```

Groq периодически снимает модели с обслуживания — тогда приложение сообщит, что модель
недоступна. Актуальный список: [console.groq.com/docs/models](https://console.groq.com/docs/models).
Нужна модель с поддержкой JSON mode (`response_format: json_object`). Проверенные варианты:
`openai/gpt-oss-120b` (качество, по умолчанию), `openai/gpt-oss-20b` и `qwen/qwen3.8-27b` (быстрее).

Без ключа приложение запускается и работает — недоступны только AI-функции
(оценка открытых ответов, ревью кода, догенерация контента, mock interview).
Бэкенд напишет об этом в лог при старте, фронтенд покажет подсказку на месте AI-кнопок.

Ключ читает **только бэкенд**. Фронтенд ходит за AI исключительно через `/api/ai/*`.

## Запуск

```bash
npm run dev
```

Одна команда поднимает оба процесса через `concurrently`:

- бэкенд — http://127.0.0.1:3001
- фронтенд — http://127.0.0.1:5173 (запросы `/api/*` проксируются на бэкенд)

При первом старте бэкенд сам накатывает миграции и загружает seed-контент в `data/app.db`.

### Остальные команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | фронт + бэк в режиме разработки |
| `npm run build` | продакшен-сборка фронтенда |
| `npm run typecheck` | `tsc --noEmit` по всем воркспейсам |
| `npm run lint` | ESLint (в том числе запрет `any` и правила хуков) |
| `npm run db:migrate` | накатить новые миграции |
| `npm run db:seed` | перезалить seed-контент (прогресс не трогает) |
| `npm run db:reset` | **удалить базу** и создать заново — прогресс потеряется |
| `npm run validate:tasks` | прогнать эталонные решения всех задач через их тесты |

## Как добавлять свой контент

Весь базовый контент лежит в `server/src/seed/` обычными TypeScript-файлами и грузится
в SQLite при старте. Сид **идемпотентен**: тексты обновляются, а прогресс, заметки,
попытки и состояние карточек сохраняются.

### Новая тема роадмапа

`server/src/seed/roadmap.ts` — найдите нужный этап и добавьте объект в `topics`:

```ts
{
  slug: 'my-topic',              // используется как id и как адрес /topic/my-topic
  title: 'Название темы',
  summary: 'Одно-два предложения: что именно спрашивают на собеседовании',
  estimatedMinutes: 60,
  subtopics: ['Первый пункт', 'Второй пункт'],
}
```

Затем `npm run db:seed`. Тема, удалённая из seed-файла, удаляется и из базы вместе
с прогрессом по ней — переименование `slug` равносильно удалению и созданию новой темы.

### Теория

`server/src/seed/theory/<slug темы>.md` — один файл на тему. Первый заголовок первого
уровня становится названием статьи и из тела вырезается (на странице он выводится отдельно).
Поддерживается GFM: таблицы, списки, подсветка кода для `js`, `ts`, `tsx`, `jsx`, `html`.

### Вопросы

`server/src/seed/questions/` — массивы `SeedQuestion[]`, собираются в `index.ts`.
Три типа:

```ts
// multiple choice (correct может содержать несколько id)
{ topic: 'closures', kind: 'mc', difficulty: 'easy',
  promptMd: 'Вопрос?', options: [{ id: 'a', text: '...' }], correct: ['a'],
  explanationMd: 'Разбор' }

// что выведет код; без options — свободный ввод построчно
{ topic: 'event-loop', kind: 'output', difficulty: 'medium',
  promptMd: 'Что выведет?', code: 'console.log(1)',
  expectedOutput: ['1'], explanationMd: 'Разбор' }

// открытый вопрос: оценивает AI (или вы сами по эталону, если ключа нет)
{ topic: 'closures', kind: 'open', difficulty: 'medium',
  promptMd: 'Объясните...', referenceAnswerMd: 'Эталон',
  rubric: ['что должно прозвучать'], explanationMd: 'Заметка' }
```

### Флеш-карточки

`server/src/seed/flashcards/` — массивы `SeedFlashcard[]`:

```ts
{ topic: 'closures', front: 'Вопрос карточки', back: 'Ответ в Markdown' }
```

### Задачи

`server/src/seed/tasks/` — массивы `SeedTask[]`:

```ts
{
  slug: 'chunk',                  // адрес /tasks/chunk и id в базе
  topic: 'arrays-strings',
  title: 'chunk — разбить массив на группы',
  kind: 'algo',                   // algo | react | review
  difficulty: 'easy',
  statementMd: 'Условие в Markdown',
  starterCode: `function chunk<T>(items: T[], size: number): T[][] {
  return [];
}`,
  solutionCode: '...',            // эталон, показывается только по кнопке
  solutionNotesMd: 'Разбор: сложность, ловушки, альтернативы',
  hints: ['Подсказка 1', 'Подсказка 2'],   // открываются по одной
  tests: [
    { name: 'разбивает нацело', code: 'expect(chunk([1,2,3,4], 2)).toEqual([[1,2],[3,4]]);' },
    { name: 'граничный случай', code: '...', hidden: true },
  ],
}
```

**Тесты пишутся на чистом JavaScript**, без TypeScript-синтаксиса: транспилируется
только код решения, а тесты подставляются как есть. В тестах доступны `expect`,
`deepEqual` и `sleep`; тело теста асинхронное, поэтому `await` работает.

Матчеры: `toBe`, `toEqual`, `toBeCloseTo`, `toBeTruthy`, `toBeFalsy`, `toBeNull`,
`toBeUndefined`, `toBeDefined`, `toBeInstanceOf`, `toHaveLength`, `toContain`,
`toThrow` и `.not` перед любым из них.

После правки задач обязательно прогоните:

```bash
npm run validate:tasks
```

Скрипт проверяет, что эталонное решение каждой задачи проходит её тесты, а стартовый
код — нет (иначе задача ничего не проверяет).

**Про «скрытые» тесты.** Они не показываются в интерфейсе до прогона, но приходят
на клиент вместе с задачей — иначе их нельзя было бы выполнить в браузере.
Это личное приложение для подготовки, а не олимпиадная платформа: смысл скрытых
тестов в том, чтобы не подсказывать граничные случаи заранее, а не в защите от списывания.

### React-задачи

React-задача — это TSX-модуль с `import` и `export`, который исполняется в **sandbox-iframe**
с настоящим DOM и живым превью. Отличия от обычной задачи:

```ts
{
  slug: 'react-counter',
  topic: 'state-hooks',
  kind: 'react',                 // или 'review' для задач «найди и исправь»
  runtime: 'preview',            // исполнять в iframe; язык по умолчанию — tsx, лимит — 3000 мс
  starterCode: `import { useState } from 'react';

export function Counter() { … }          // что тестируем — именованный экспорт

export default function App() {          // что показывает превью
  return <Counter />;
}`,
  tests: [
    {
      name: 'клик увеличивает',
      code: `await render(h(exports.Counter));
await fireEvent.click(screen.getByRole('button', { name: '+' }));
expect(screen.getByTestId('value').textContent).toBe('1');`,
    },
  ],
}
```

- Импортировать можно только `react` и `react-dom`. Превью показывает `export default`
  (или экспорт `App`).
- Экспорты модуля в тестах доступны как `exports.Имя`.
- Тесты — чистый JavaScript без JSX: элементы создаются через `h` (= `React.createElement`).
- Помощники — мини-версия Testing Library. **Все действия асинхронные — нужен `await`**:
  `render(el)` → `{ container, rerender, unmount }`, `renderHook(fn, { initialProps })`,
  `screen` и `within(el)` с запросами `getBy/queryBy/getAllBy/findBy` + `Role`, `Text`,
  `LabelText`, `TestId`, `PlaceholderText`, `DisplayValue`;
  `fireEvent.click/change/type/submit/keyDown/blur/focus`; `act`, `waitFor`, `sleep`.
- Между тестами DOM очищается, а `globalThis.fetch` восстанавливается — его можно подменять
  прямо в тесте.

`npm run validate:tasks` проверяет React-задачи в Node: в отдельном потоке с happy-dom.
Тот же код хелперов работает и в браузере (`shared/src/reactTesting.ts`).

**Безопасность превью.** Iframe открывается без `allow-same-origin`, поэтому у кода задачи
нет доступа к приложению, его `localStorage` и cookies. Бесконечный цикл в тестах ловит
таймер, после чего iframe удаляется. Превью, которое не ответило за 4 секунды, пересоздаётся
после следующей правки кода.

**Идентификаторы не пишутся руками**: они выводятся из содержимого (тема + формулировка).
Поэтому вставка вопроса в середину файла не сбивает историю попыток и состояние SM-2
у соседей, а правка формулировки создаёт новую сущность.

### Догенерация через AI

Кнопки «сгенерировать ещё вопросов» и «сгенерировать похожую задачу» сохраняют результат
в базу с пометкой `source = 'ai'` — в интерфейсе такой контент помечен бейджем, чтобы
выверенный вручную материал был отличим от сгенерированного. Перед сохранением задачи
её эталонное решение прогоняется через её же тесты; если не проходит — задача отбрасывается.
«Похожая задача» наследует тип образца: для React-задачи генерируется React-задача,
и её эталон проверяется в DOM-окружении.

Где кнопки:

- **Квиз темы** → блок «Добавить вопросы через AI» внизу (1–5 штук, можно задать тип и сложность).
- **Открытый вопрос** → после ответа «Оценить через AI»: оценка 0–10, что упущено,
  эталон, ответ сильного кандидата и follow-up вопросы. Самооценка остаётся доступной.
- **Страница задачи** → «AI-ревью моего решения» (ревьюится последняя запущенная попытка,
  ревью сохраняется в истории) и «Сгенерировать похожую задачу».

### Mock interview

Раздел **Интервью**: выберите формат (теория JS, теория React, live-coding, смешанное
техническое, поведенческое) и длительность. AI-интервьюер задаёт по одному вопросу и после
каждого ответа решает: копнуть глубже (follow-up), перейти к новой теме или выдать задачу
в редактор. В live-coding код можно запустить в той же песочнице и отправить вместе с ответом.

- Оценки ответов скрыты до конца интервью и появляются в транскрипте вместе с отчётом.
- Отчёт: общая оценка и вердикт, сильные и слабые стороны, оценки по темам, план действий.
- Темы с оценкой ниже 6 и темы, которые интервьюер назвал явно, получают в роадмапе
  статус **«повторить»** и попадают в слабые темы на дашборде.
- Черновик ответа и код сохраняются в браузере — обновление страницы их не теряет.
  Незавершённое интервью можно продолжить со страницы раздела.
- Каждый ход интервьюера — один запрос к Groq. На бесплатном тарифе при частых ответах
  возможен 429: ответ не теряется, достаточно нажать «Повторить».

### Лимиты бесплатного тарифа Groq

На 429 бэкенд делает до трёх попыток с экспоненциальной задержкой и учитывает заголовок
`retry-after`. Если Groq просит ждать дольше 30 секунд, запрос не висит — интерфейс
сразу покажет, через сколько секунд можно повторить.
